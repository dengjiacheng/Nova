# 治理路线

## 核心指标（KPI）

- **可靠性**  
  - Agent 在线率 ≥ 99%，心跳延迟 P95 ≤ 3s  
  - 脚本执行成功率 ≥ 97%，平均执行时长 ≤ 120s
- **质量**  
  - 覆盖率：NovaServer/NovaAgent/NovaDesk 单元 + 集成测试覆盖率 ≥ 75%  
  - 关键路径（脚本下发、设备上线、资产同步）端到端回归完成率 ≥ 95%  
  - 缺陷逃逸率 ≤ 0.5 / 迭代
- **效率**  
  - DCP → 首个 Code PR 中位时间 ≤ 2 天  
  - 需求 Lead Time ≤ 7 天，阻塞项跟踪在 RFC/Issue 中
- **安全**  
  - 高危漏洞（CVSS ≥ 9）72 小时内修复  
  - 季度安全评估覆盖 100% 对外接口与守护脚本

## 两周接手落地

| 周次 | 目标 | 关键产出 |
| ---- | ---- | -------- |
| Week 1 | 建立权威文档、评估现状 | 文档骨架、运行/部署手册、指标草案、覆盖率现状报告 |
| Week 2 | 完成测试补强与治理闭环 | 三端覆盖率 ≥ 75%、CI 守门策略、KPI 看板需求与例行模板 |

### Week 1 行动

1. 整理 `docs/reference`，补齐运行、协议、应急、依赖治理等章节；
2. 抽取覆盖率命令并写入测试基线文档；
3. 汇总现有监控指标，确认缺口与数据源；
4. 在守护/CI 中记录 DCP → 文档 → 代码流程。

### Week 2 行动

1. 执行测试补强计划（单元 + 端到端），关注高风险链路；
2. 配置覆盖率阈值、质量守门脚本，保证报告产出与归档；
3. 输出 KPI 看板结构、周会/复盘模板、风险日志格式；
4. 建立例行审查安排（双周治理会、月度复盘）。

## 季度治理节奏

| 时间节点 | 主要事项 | 产出 |
| -------- | -------- | ---- |
| 季初（Week 1-2） | 依赖升级扫描、协议审视、风险矩阵复盘 | 升级计划、兼容性评审、风险清单 |
| 季中（Week 5-6） | 重点功能迭代、测试矩阵扩充、观测指标校准 | 迭代计划、测试白名单、监控阈值调整 |
| 季末（Week 11-12） | 发布评审、回归测试、指标复盘 | 发布清单、指标公报、治理改进项 |

## 组织角色

- **平台技术负责人**：把控架构方向、审批 DCP、统筹跨端资源；
- **后端负责人**：维护 NovaServer、数据库策略、安全合规；
- **客户端负责人**：负责 NovaAgent/NovaDesk 路线与联调；
- **SRE/QA 团队**：执行测试/覆盖率守门、维护 CI/CD、搭建指标看板；
- **产品/运营代表**：提供 KPI 业务指标反馈，协助定义优先级。

## 治理守则

1. 任何改动须先更新 DCP 与 Reference，确认风险与回滚方案；
2. 模块级 PR 必须附带自动化测试与风险评估；
3. 每月执行一次自动化演练（守护脚本、灾备切换、回滚测试）；
4. 安全扫描（SAST/DAST、依赖扫描）纳入 CI，并作为合并守门；
5. KPI 与风险矩阵在例会中复盘，行动项回写至 Reference 与 DCP。
